## 4. Что даёт H1 около 90 px и H2 около 70 px

Оба размера приходят **пресетами `theme.json`**, а не числами
в CSS:

```
heading-l  clamp(2.75rem, 2.1432rem + 2.589vw, 5.25rem)   44 → 84 px
heading-m  clamp(2.25rem, 1.8252rem + 1.812vw, 4rem)      36 → 64 px
heading-s  clamp(1.375rem, 1.2539rem + 0.518vw, 1.875rem) 22 → 30 px
```

Применяются они правилами `main.css:200` (H1) и `main.css:222` (H2).

**Где ещё используются те же пресеты** — это важно, потому что
правка пресета заденет всё разом:

| Пресет | Где |
|--------|-----|
| `heading-l` | `.wp-block-post-title` (все типы записей), `.wp-block-query-title` (заголовок архива), `h1.wp-block-heading`, `.entry-content > h1`, класс `has-heading-l-font-size` в разметке |
| `heading-m` | `.entry-content h2`, `styles.elements.h2` в `theme.json`, `editor-styles.css` |
| `heading-s` | карточки услуг в каталоге и на главной, `styles.elements.h3` |

**Вывод для задачи 3:** пресеты не трогать, новые размеры задавать
правилами со скоупом `body.single-services`. Обойти пресет можно —
в шаблоне у `post-title` `fontSize` не указан намеренно, и класс
`has-heading-l-font-size` с `!important` на него не попадает.

## 6. Паттерны, сборка, транзиент

**В `patterns/` один файл** — `service-page.php` (239 строк),
slug `razil/service-page`, категория `razil`, `Block Types:
core/post-content`, `Inserter: true`.

**Категория `razil` нигде не регистрируется.**
`register_block_pattern_category` не встречается ни в теме,
ни в плагине. Задача 4 заводит категорию «Услуга».

**WordPress 7.0.2.**

**Сборка.** `package.json`: `build` = `wp-scripts build`,
`start`, `lint:js`, `lint:css`. Единственная зависимость —
`@wordpress/scripts`.

**`build/` отслеживается в git** — 40 файлов, и это намеренно:
в `.gitignore` стоит пояснение «functions.php регистрирует блоки
из `build/blocks/*`, сборки на сервере нет, и без этого каталога
свежий клон остаётся без всех блоков темы».

Важное: в `build/blocks/*` лежат **только `block.json` и
`render.php`** — ни одного собранного JS. Все семнадцать блоков
темы серверные. Значит `register_block_style()` из PHP сборки
не требует: WordPress сам передаёт зарегистрированные стили
в редактор через реестр типов блоков.

**Транзиент паттернов.**
`wp-includes/class-wp-theme.php:2008` —
`wp_theme_files_patterns-<cache_hash>`, где `cache_hash` свой
у каждой темы. Сбрасывается двумя способами:

```php
wp_get_theme()->delete_pattern_cache();   // wp-includes/class-wp-theme.php:2064
```

или поднятием `Version` в `style.css` — кэш хранит версию темы
и при несовпадении перечитывает файлы. Сейчас версия `1.0.0`.

## 7. Телефон, кнопки, шорткод

**Где хранится.** Опция `razil_org` (Настройки → Организация),
модуль `razil-core/inc/org-settings.php`.

```php
razil_org( 'phone' )        // «+7 (4212) 60-52-90»
razil_org( 'phone_legal' )  // «+7 (962) 151-42-57»
razil_org_tel( 'phone' )    // «tel:+74212605290»
```

**Как номер попадает на страницу.** Не функцией в шаблоне,
а **подменой в готовом HTML**: `razil_org_buffer()` вешается
на `template_redirect`, открывает `ob_start` и на выходе меняет
резервные написания на значения из настроек
(`org-settings.php:600–775`). Резервные написания стоят прямо
в файлах темы: `parts/header.html` (три раза), `parts/footer.html`,
`parts/sticky-call.html` и другие.

**Вывод для задачи 4.** В паттерне номер пишется **резервным
значением, дословно как в шапке** — `+7 (4212) 60-52-90`
и `href="tel:+74212605290"`. Вызывать `razil_org()` прямо
в паттерне **нельзя**: паттерн вставляется в запись один раз,
результат вызова застынет в базе, и карта замен (она ищет
резервное написание) его уже не найдёт — номер протухнет при первой
же смене настройки. Это ровно тот механизм, ради которого буфер
и написан.

**Что открывает «Вызвать специалиста» в шапке.** Разметка:

```html
<div class="wp-block-button">
  <a class="wp-block-button__link wp-element-button" href="tel:+74212605290">Вызвать специалиста</a>
</div>
```

Это **ссылка на телефон, а не форма.** `header.js:190–245`
перехватывает клик по `a[href^="tel:"]` **только если** ссылка
лежит внутри `.wp-block-button` и указатель не сенсорный —
и показывает окно подтверждения `.rz-tel-dialog` («Позвонить
в агентство?» + номер + кнопки «Позвонить»/«Отмена»). На телефоне
ссылка отдаётся системе как есть.

**Шорткод `[razil_callback_button]`** —
`razil-core/inc/callback-form.php:243–290`. Атрибуты:

```
label  подпись кнопки, по умолчанию «Перезвоните мне»
class  ОДИН дополнительный класс (пропускается через
       sanitize_html_class, пробелы не переживёт)
```

Печатает `<button class="wp-element-button rz-cb-open …"
data-rz-cb-open>` и рядом — `<dialog id="rz-cb-dialog">`
с настоящей формой, которая без JavaScript отправляется обычным
POST. Окно выводится один раз на страницу, сколько бы кнопок
ни стояло.

**Расхождение спецификации с кодом, найденное здесь.**
Задача 4 требует, чтобы кнопка «Вызвать специалиста» в первом
экране «открывала ту же форму, что кнопка в шапке». Кнопка в шапке
формы не открывает вовсе — она звонит. Разбор и выбранное решение
записаны в отчёте прогона, раздел задачи 4.

## 8. Что мешает `align: full` иметь фон от края до края

Три вещи, и все три — в шаблоне, а не в CSS.

1. **`styles.spacing.padding` в `theme.json` не задан.** При
   `useRootPaddingAwareAlignments: true` ядро вытягивает
   полноширинный блок отрицательными полями, равными корневому
   отступу: `.has-global-padding > .alignfull { margin-right:
   calc(var(--wp--style--root--padding-right) * -1) }`. Корневой
   отступ нулевой — вытягивать не на что.

2. **Боковые поля приходят инлайновым стилем обёртки.**
   `templates/single-services.html:3` — `padding-right:1rem;
   padding-left:1rem` прямо в атрибуте блока. Ядро об этих полях
   не знает и компенсировать их не умеет.

3. **`post-content` выводится с раскладкой «поток», а не
   «ограниченная».** В готовой странице это
   `div.entry-content.wp-block-post-content.is-layout-flow` —
   без `has-global-padding`. Правило ядра для `.alignfull`
   к такому родителю не применяется вовсе.

**Как полноширинный фон сделан сейчас** — обходным приёмом
(`main.css:4323`):

```css
.entry-content .rz-sec:nth-child(even) {
	background-color: var(--rz-surface);
	box-shadow: 0 0 0 100vmax var(--rz-surface);
	clip-path: inset(0 -100vmax);
}
```

Тень с нулевым размытием заливает поля, `clip-path` обрезает разлив
по вертикали. Раскладку это не трогает, горизонтальной прокрутки
не даёт. **Но фон — единственное, что так растягивается:**
сама коробка секции остаётся в контейнере, и фотография до края
окна этим приёмом не выносится. Для первого экрана на телефоне
(«фото до края») приём не годится, нужна настоящая полноширинность.

## 9. `inc/schema.php` — FAQPage и Service

`wp-content/plugins/razil-core/inc/schema.php`.
Вешается на фильтр `wpseo_schema_graph` (строка 65).

**FAQPage** (`razil_schema_add_faq`, строки 106–320):

## 10. `inc/first-image.php` — кому eager и fetchpriority

Отбор **по классу блока**, не по порядку в документе:

```php
const RAZIL_LEAD_IMAGE_CLASSES = array( 'rz-service-photo', 'rz-contacts__photo' );
```

Фильтр `render_block` на `core/image`: первому блоку с таким
классом `loading="lazy"` меняется на `eager` и дописывается
`fetchpriority="high"`. Счётчик статический — срабатывает один раз
на запрос.

**Риск для задачи 4.** Новый первый экран выводит снимок блоком
`core/post-featured-image`, а не `core/image`, и класса
`rz-service-photo` у него нет. Под условие фильтра он не попадает
вовсе. Проверить после задачи 12 и, если снимок получил
`loading="lazy"`, точечно расширить фильтр — И5 это прямо
разрешает с обоснованием.

## Риски

1. **Крошки живут в шапке, а не в шаблоне услуги.** Любая правка
   их вида обязана быть ограничена `body.single-services`, иначе
   заденет все четырнадцать шаблонов.

2. **Alt пяти снимков живёт только в разметке блока**, в медиатеке
   пусто. Перенос в изображение записи потеряет alt, если его
   не скопировать отдельно. П18 требует alt у всех изображений.

3. **`mikroavtobus.webp` — 720 px в ширину** при требовании
   «не уже 1100 px для первого экрана». Задание велит записать
   в отчёт и не подменять.

4. **`data-accordion` делает группу невалидной в редакторе.**
   Правило «открыт только один» держится на этом атрибуте
   (`header.js:403`). Перевод правила на класс — часть задачи 10.

5. **Атрибуты `width/height/loading/decoding` у `core/image`
   в базе** делают блок невалидным: их приписывает вывод, а не
   `save()`. В новой разметке их быть не должно.

6. **`first-image.php` не увидит `core/post-featured-image`** —
   первый экран рискует получить ленивую загрузку.

7. **Пресеты `heading-l` и `heading-m` общие на весь сайт.**
   Новая типографика услуги обязана идти скоупом, а не правкой
   пресета.

8. **У `.rz-side--photo-right` ширина снимка подобрана вручную**
   (73.5 % колонки, `main.css:3328`) под фактическую высоту текста
   каждой страницы. Новый первый экран этой подгонки не наследует —
   пропорцию придётся задавать заново.

9. **Кнопка «Вызвать специалиста» в шапке формы не открывает.**
   Спецификация задачи 4 исходит из обратного.

10. **Полноширинность сейчас — обходной приём** (тень + `clip-path`),
    фотографию до края окна он не выносит. Задача 3 обязана
    заменить его настоящей раскладкой, не сломав старый контент.
